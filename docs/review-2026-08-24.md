## New findings — the new work reviewed adversarially

### N-A. The safety layer's composition (the important ones)

**N1 — HIGH. Nothing runs the new safety layer.** The watchdog plist says it itself:
"NOTHING HERE HAS EVER BEEN LOADED." One manual `watch-health` run exists. The digest is
scheduled only in code the instance doesn't run (L2). The acknowledged dead-man's-switch
gap (a healthchecks.io ping so the *watcher's* death is noticed) remains open — and it is
five minutes of work per the project's own runbook. Until the launchd bootstrap + hc-ping
happen and the instance is redeployed, the operational value of ~7k lines of new safety
code is zero. Yesterday's A1 is "fixed" in code and open in reality.

**N2 — HIGH. The digest's flagship rules can never fire on their schedule.**
`digest_daily` runs 06:00 local reviewing D-1 — but D-1's Bryant `eheat` lands at
**08:30** and D-1's meter data at **09:15 or later** (LG&E publishes late). So the
strip-heat rule reads absent-as-zero and returns silently every scheduled night
(`digest.py:518`), the barn envelope sees no rows, and `meter_disagreement` — the only
check that can see a mis-scaled clamp — is skipped as "no overlap". The digest never
re-checks a day once its data arrives, so **the three most valuable checks never execute
in the automated pipeline.** Fix: run the digest ~10:00, or point those rules at D-2/D-3.

**N3 — HIGH. Digest and integrity failures are invisible to the watchdog.** Neither
writes its own status section on failure (`digest` lands in the shared `scheduler` section
the watcher deliberately ignores); `_job_digest` catches **all** exceptions on import and
returns `{"skipped": "not_implemented"}` — a job *success* — so a genuinely broken digest
module is disguised forever (`runtime.py:612-616`; its neighbor `_job_bryant_daily`
documents exactly why this is wrong and re-raises). And a quiet night is indistinguishable
from a dead digest on the phone: the skip accounting is never delivered when findings are
zero, and there is no heartbeat. Fix: a `digest` status section + a watch rule ("ran
within 26h"), the narrow import guard, and a weekly `always_notify` digest.

**N4 — MEDIUM. A failed Pushover delivery suppresses its own retry.** `watch.py` records
the new alarm set whether or not the push landed, so "changed" never re-fires — a
brand-new CRITICAL during a Pushover outage stays silent for up to six hours. Advance the
state only on delivered.

**N5 — MEDIUM. A repeat of #177 still takes ~3 days to page.**
`GreenbuttonAuthorizationRevoked` raises *before* the stage runs, so it lands only in the
ignored `scheduler` section; nothing ever calls `record_failure("greenbutton")`, making
the watcher's `greenbutton` streak rule **dead code — no writer can fire it**. Detection
falls through to meter staleness (3 days, WARNING). Today's L1 is this finding happening.

**N6 — MEDIUM. The band can normalize faults.** A slowly failing appliance walks the
21-day median up inside the band; a fired-and-ignored step fault becomes the new median in
~11 days and stops alarming (no acknowledgment state). Recovered channels also readmit
their *frozen* history days to the baseline (the untrusted check runs only on D-1). And a
channel or whole hub that emits **no rows** today is neither compared nor named in any
skip list; a whole hub latched at zero evades both `frozen_channel` (zeros excluded) and
`feed_below_children` (0 ≤ 0) — only the meter check can see it, and per N2 it never runs.
These are honest limitations to write down (some are in DEVIATIONS #191), plus one real
gap: `BARN_MIN_KWH` is dead code — the barn's "EV silently stopped charging" side has no
check, and the barn device is discovered by `"barn" in short_label`, which a rename turns
off silently.

**N7 — MEDIUM. The `SCHEDULED_JOBS` knob's own recommended split config silently disables
the spool purge.** The knob selects whole jobs; `daily_maintenance` bundles upload
catch-up + compact + re-roll + **purge**, and nothing else purges. The docstring,
`.env.example`, and a test all showcase a poller that omits `daily_maintenance` — that
collector never purges (unbounded spool) and loses upload catch-up. Yesterday's A2-class
lesson again: job granularity ≠ responsibility granularity. Harmless today (default = all
jobs); it bites the day the knob is used as advertised.

### N-B. Billing layer residue

**N8 — MEDIUM (B7's remaining class). The >1-primary guard was never built.**
`compare.py` now reads `primary is True`, but `dim.py:510` still coerces with `bool()`
(`"primary": "no"` → True), `meterview` still tests truthiness, and *nothing* enforces
at-most-one primary per source — a hand-edit slip still makes `historyview` silently sum
house + barn, and its `>=` interval gate would pass the doubled count as "complete." One
assertion in `build-dim` closes the class. **With the house now in the table under three
device ids (L3), this guard matters more than it did yesterday.**

**N9 — LOW-MEDIUM. `verify-bill`'s help promises a primary default it doesn't implement**
(`cli.py:1054` vs `verify_bill.py:421` — a bare run raises `AmbiguousMeterError`; the
README recipe passes `--meter` so it works as documented), and one CLI docstring states
the cycle-boundary convention **backwards** (`cli.py:1092`: "--end … is EXCLUSIVE" — the
code and every other document treat the end read date as billed and the start as
excluded). The code is right; the help text is the off-by-one the module was written to
kill. Also: the `/ui` meter card's B1 gate silently degrades to pre-B1 behavior if the
channel map isn't at the CWD-relative path (fine in the container, silent elsewhere), and
`intervals > expected` — always evidence of a bug — is accepted as "complete" rather than
refused.

### N-C. Pipeline-core nuances

**N10 — MEDIUM (nuance worth recording). `observed_seconds` records the pricing
assumption, not a measurement.** It is `sample_count × configured_interval` — the guard
validates the assumption to ±25%, and inside that band the column *asserts* 30s under a
name that claims observation; the kWh self-check against it is tautological. The cheap
hardening is to also store the measured median spacing (already computed by the guard).
Also, three loud-but-sharp edges: the guard is silent under 20 deltas/day; `compare.py`
and the scheduled jobs have no `--allow-interval-mismatch` escape hatch, so a legitimate
future interval change fails the instance's rollups for the transition day; and a
mixed-cadence day forced through with the flag prices the minority rows wrong with only a
WARN.

**N11 — Assessment note on IAM v3.** The stated cost ("the internet-facing box can now
overwrite derived data") is accurate but two details sharpen it: v2 already let the
collector overwrite `raw_30s` (that exposure isn't new — what v3 newly surrenders is the
parts archive, which was only ever a 14-day safety net), and the real mitigation is bucket
versioning, which is **time-boxed at 30 days** — "worst case is re-run a stage" assumes
the compromise is detected inside that window. True under v2 as well; worth one sentence
in #181.

**N12 — LOW.** The D1 fix has two same-class leftovers: a manual historical fetch
*rewinds* `newest_interval_utc` (false staleness alarm — the safe wrong direction; fix is
`max(stored, fetched)`), and a zero-row fetch still overwrites the stored `meters` list
with `[]`. Concurrent instance/Mac rollups were checked: per-writer UUID temp keys,
atomic copy, worst case a ≤1h self-healing regression of the open day — acceptable.

## What is genuinely solid in the new work

- **The tariff engine's grounding standard.** Reproducing twenty real bills to the cent —
  fuel adjustment inside the rider base on Residential only, the barn's rider-base
  deduction, HEA untaxed, sales tax on top of school tax, credit riders — with
  `first_seen_on_bill` provenance on every number, and *measured* cycle-boundary semantics.
  This is the right way to encode a tariff and it makes stale rates self-detecting.
- **The interval guard's design**: median-of-deltas (a gapped day is not slow cadence — the
  gap test actively re-proves rule 1), refusal not rescale, the factor named in the error,
  and DST fixtures forced honest rather than the guard weakened.
- **`watch.py`'s absence-is-failure discipline** — an empty document raises five alarms;
  503-with-body still parsed; corrupt state fails open (sends); the anti-fatigue push
  policy. The design is right; only deployment and N4/N5 stand between it and usefulness.
- **The migration hygiene**: `union_by_name` on every hourly reader with a real
  mixed-archive test, Glue regenerated from the schema, the full re-roll Athena-verified.
- **conftest deny-by-default isolation** — the class fix, verified against `model_fields`,
  no aliases/prefix to slip through.
- Idempotency, no-fabrication, dedupe, and DST were all re-checked against the diff:
  intact.
